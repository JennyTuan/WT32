# WT32 常规扫描模块测试用例

## 1. 测试范围

本文档覆盖 WT32 CT 控制台原型的常规扫描模块测试用例，用于产品和 UI 验证，不用于真实设备控制、临床诊断、治疗决策或最终剂量确认。

本轮测试包含：

- 登录与基础导航
- 患者选择与检查上下文
- 常规协议选择与协议参数查看/编辑
- 定位像准备、确认、执行
- 常规螺旋扫描确认、执行、完成后图像查看
- 常规轴扫协议的数据、参数和可达流程验证
- 重建参数、预计/参考剂量显示
- 扫描会话副本、刷新恢复、取消流程、接口与数据一致性

本轮暂不包含：

- 呼吸门控扫描，包括 gated helical、gated axial、DIBH、自由呼吸触发
- 4D CT，包括呼吸训练、时相回顾、重扫选择
- DOM / 智能剂量调节，包括自动 mA 曲线、上下限调节、DOM 日志专项
- 服务模式、移动端模式、真实 DICOM 导入专项、权限管理专项

## 2. 测试优先级定义

| 标记 | 含义 | 准入要求 |
| --- | --- | --- |
| Smoke | 冒烟用例，验证系统是否可进入主流程 | 每次测试构建必须全部通过 |
| P0 | 主链路与数据安全关键用例 | 发布前必须全部通过 |
| P1 | 重要功能与主要异常路径 | 发布前应通过，失败需评估风险 |
| P2 | 兼容性、边界体验、弱网/刷新等补充覆盖 | 可按版本节奏安排 |

## 3. 测试前置条件

- 后端服务已启动：`http://localhost:8000`
- 前端服务已启动：`http://localhost:5175`
- 使用本地测试账号登录：`U0001 / stn123456`
- 数据库存在至少一个 `acquisition_type=regular` 的常规协议
- 常规协议至少包含一个定位像序列和一个螺旋或轴扫序列
- 浏览器缓存可按需清理，重点关注 `localStorage` 中患者、协议和扫描会话状态

## 6. 回归测试建议

每次修复常规扫描模块后，至少执行：

- 全部 Smoke 用例
- `REG-SESSION-001` 到 `REG-SESSION-004`
- 对应改动页面的 P0/P1 用例
- 若涉及参数、接口或数据模型，补跑 `REG-API-003` 到 `REG-API-007`
- 若涉及剂量显示，补跑 `REG-DOSE-001` 到 `REG-DOSE-004`

## 7. 测试通过标准

- Smoke 全部通过。
- P0 全部通过，无阻塞性缺陷。
- P1 缺陷必须有明确风险评估和处理结论。
- 常规扫描流程不得误入门控、4D 或 DOM 专项路径。
- 会话参数编辑不得污染协议模板。
- 剂量、对比剂、安全相关文案不得暗示真实设备控制、诊断结论、治疗建议、保证安全或最终剂量批准。
