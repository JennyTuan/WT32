# 剂量日志页面修改计划

## 1. 修改目标

当前“剂量日志”页面已经具备基础列表、筛选和状态展示能力，但现有结构更偏向单条日志平铺展示。考虑后期将扩展增强扫描、多期扫描、4D 扫描、DOM 剂量调节、剂量告警和人工确认等能力，建议将页面信息架构调整为：

> 以“检查级 Exam”为主列表对象，以“序列/期相级 Series / Phase”为展开明细对象。

修改后的页面应支持：

- 常规 CT 平扫剂量记录；
- Scout / 定位像剂量参数展示；
- 增强扫描多期剂量展示；
- 4D 扫描剂量展示；
- DOM 是否启用的记录；
- 剂量告警与人工确认；
- 后续剂量统计、质控、报告导出扩展。

---

## 2. 当前页面主要问题

### 2.1 列表主对象不清晰

当前列表每一行看起来像一条剂量日志，但业务上可能混合了：

- 一次检查；
- 一个扫描序列；
- 一个 4D 扫描任务；
- 一个待确认剂量记录。

后期扩展增强扫描时，一个检查可能包含平扫、动脉期、静脉期、延迟期等多个序列。如果仍然采用单行平铺，会出现以下问题：

- 总 DLP 与单期 DLP 容易混淆；
- 增强各期剂量无法清晰归属；
- 4D、多序列检查难以展示；
- 剂量确认对象不明确。

### 2.2 患者累计剂量展示位置不合理

当前患者姓名下方展示“累计 DLP”，该信息有价值，但不应作为列表主信息反复出现。

剂量日志页面的主任务是查看本次检查剂量、确认记录、识别异常，而不是患者长期累计剂量回顾。

建议将患者累计剂量移动至详情抽屉或检查详情页中展示。

### 2.3 “协议 / 部位”字段承载过多

当前“协议 / 部位”列同时展示协议、部位和英文部位信息。后期增强扫描扩展后，还需要展示检查类型、期相信息、协议名称等内容，当前字段结构不利于扩展。

建议拆分为：

- 检查；
- 协议；
- 类型；
- 期数。

### 2.4 DOM 信息权重过高

当前顶部统计中包含“DOM 启用”。如果页面定位是剂量日志，核心关注应优先是：

- 全部检查；
- 待确认；
- 剂量告警；
- 增强检查 / DOM 介入。

DOM 应作为筛选条件或标签信息保留，不建议作为页面最核心统计指标。

### 2.5 缺少剂量告警维度

剂量日志页面不仅要记录剂量，还应帮助用户快速识别剂量异常。因此需要增加：

- 是否超阈值；
- 告警等级；
- 告警原因；
- 是否已确认。

## 3. 总体修改方案

### 3.1 页面主列表粒度

主列表一行代表一次检查，即 Exam 级记录。

每条检查记录汇总展示：

- 患者信息；
- 检查信息；
- 协议信息；
- 检查时间；
- 检查类型；
- 期数；
- 本次总 DLP；
- CTDIvol；
- DOM 状态；
- 确认 / 告警状态。

### 3.2 明细层级

每条检查记录支持展开，展开后展示该检查下的序列或期相明细。

明细可包含：

- Scout / 定位像；
- 平扫；
- 动脉期；
- 静脉期；
- 延迟期；
- 4D 扫描序列；
- 其他特殊扫描序列。

---

## 4. 页面结构修改

### 4.1 顶部统计卡修改

当前统计卡：

- 全部；
- DOM 启用；
- 已确认。

建议修改为：

| 统计项 | 含义 |
|---|---|
| 全部检查 | 当前筛选条件下的检查总数 |
| 待确认 | 尚未进行人工确认的剂量记录 |
| 剂量告警 | 存在剂量超阈值或异常的检查 |
| 增强检查 | 增强扫描检查数量 |

如果必须保留 DOM，可将“增强检查”替换为“DOM 介入”，或将 DOM 放入筛选区。

### 4.2 筛选区修改

建议筛选区支持以下条件：

| 筛选项 | 选项 |
|---|---|
| 搜索 | 患者姓名 / ID / 检查号 / 协议 |
| 日期 | 今日 / 近 7 天 / 自定义 |
| 部位 | 头部 / 胸部 / 腹部 / 心脏 / 其他 |
| 检查类型 | 全部 / 平扫 / 增强 / 4D |
| DOM | 全部 / 已启用 / 未启用 |
| 确认状态 | 全部 / 已确认 / 未确认 |
| 告警状态 | 全部 / 正常 / 告警 |

当前页面中已有搜索、DOM、确认筛选，可在此基础上新增“检查类型”和“告警状态”。

### 4.3 主列表字段修改

建议主列表字段如下：

| 字段 | 展示内容 | 说明 |
|---|---|---|
| 患者 | 姓名 + ID | 不再默认展示累计剂量 |
| 检查 | 检查名称 / 部位 | 如胸部、腹部、胸部 4D |
| 协议 | 协议名称 | 如胸部常规、腹部增强 |
| 检查时间 | 扫描完成时间 | 建议替代“创建时间” |
| 类型 | 平扫 / 增强 / 4D | 为增强扩展预留 |
| 期数 | 0 / 2 / 3 / 4 | 非增强可显示 “—” |
| 总 DLP | 本次检查总 DLP | 不包含 Scout 估算剂量 |
| CTDIvol | 代表值 / 平均值 | 根据产品规则定义 |
| 状态 | 正常 / 待确认 / 已确认 / 告警 | 可用标签展示 |
| 操作 | 展开 / 查看详情 / 确认 | 根据权限控制 |

## 5. 增强扫描扩展设计

### 5.1 增强扫描展示原则

增强扫描应作为一次检查展示在主列表中，其内部多期作为明细展示。

示例：

```text
腹部增强 CT
├─ Scout AP
├─ 平扫
├─ 动脉期
├─ 静脉期
└─ 延迟期
```

### 5.2 主列表展示规则

增强检查主列表中应展示：

- 类型：增强；
- 期数：如 3 期、4 期；
- 总 DLP：所有正式扫描序列 DLP 之和；
- CTDIvol：按产品规则展示平均值、最大值或代表值；
- 状态：若任一期超阈值，则主检查显示告警。

### 5.3 明细字段

展开后建议展示：

| 字段 | 说明 |
|---|---|
| 序列 / 期相 | Scout、平扫、动脉期、静脉期、延迟期 |
| 扫描类型 | Scout / Helical / Axial / 4D |
| CTDIvol | 序列剂量指标 |
| DLP | 序列 DLP |
| kV | 管电压 |
| mA / mAs | 管电流或有效 mAs |
| 扫描长度 | 当前序列扫描范围 |
| DOM | 是否启用 |
| 状态 | 正常 / 告警 / 已确认 |

---

## 6. Scout / 定位像剂量处理

### 6.1 展示原则

Scout 有曝光参数，也可以展示估算剂量，但不建议计入本次检查总 DLP。

主列表中的“总 DLP”应只统计正式 CT 扫描序列。

### 6.2 明细展示建议

Scout 可在展开明细中展示，建议弱化处理：

```text
Scout AP    估算剂量，仅参考，不计入总 DLP
```

建议字段包括：

- Scout 方向：AP / LAT；
- kV；
- mA；
- 曝光时间；
- 扫描长度；
- 估算剂量；
- 是否计入总 DLP：否。

---

## 7. 状态与确认逻辑

### 7.1 状态类型

建议状态统一为以下几类：

| 状态 | 含义 |
|---|---|
| 正常 | 无告警，记录完整 |
| 待确认 | 需要用户人工确认 |
| 已确认 | 用户已完成确认 |
| 告警 | 剂量超过阈值或存在异常 |
| 异常 | 记录缺失、数据异常或计算失败 |

### 7.2 告警规则建议

后续可支持：

- 总 DLP 超阈值；
- 单序列 DLP 超阈值；
- CTDIvol 超阈值；
- 增强多期累计剂量偏高；
- DOM 未启用但剂量偏高；
- 关键剂量字段缺失。

### 7.3 确认规则

建议确认对象为“检查级”。

即用户确认一次检查的剂量记录，而不是逐条确认每个序列。

但在详情页中应能看到每个序列的剂量明细。

## 8. 详情抽屉设计

点击主列表某一行后，建议右侧弹出详情抽屉。

详情抽屉包括：

### 8.1 检查摘要

- 患者姓名；
- 患者 ID；
- 检查号；
- 检查名称；
- 协议名称；
- 检查时间；
- 检查类型；
- 是否增强；
- 期数；
- DOM 状态。

### 8.2 剂量汇总

- 总 DLP；
- CTDIvol；
- SSDE，若后续支持；
- 是否超阈值；
- 告警原因。

### 8.3 序列 / 期相明细

展示每个序列的：

- 序列名称；
- 期相；
- CTDIvol；
- DLP；
- kV；
- mA / mAs；
- 扫描长度；
- 状态。

### 8.4 患者累计剂量

患者累计剂量建议放在详情抽屉中展示：

- 历史累计 DLP；
- 历史检查次数；
- 最近一次检查时间；
- 是否存在近期重复检查风险。

## 9. 适配 1024×768 的布局建议

当前设备屏幕空间有限，页面不宜增加过多列。

### 9.1 主列表优先保留字段

空间不足时，优先保留：

1. 患者；
2. 检查；
3. 检查时间；
4. 类型；
5. 总 DLP；
6. 状态；
7. 展开操作。

### 9.2 可弱化字段

以下字段可放入详情或展开区：

- 患者累计剂量；
- 英文部位；
- 完整协议参数；
- 每个序列的 kV / mA；
- Scout 估算剂量；
- 历史剂量趋势。

### 9.3 推荐主列表字段精简版

## 10. 最小改动方案

如果当前版本不适合大规模重构，建议至少完成以下 6 项：

### 10.1 明确主列表对象

每一行定义为一次检查，而不是单条序列日志。

### 10.2 修改字段名称

将“本次 DLP”改为“总 DLP”或“本次检查总 DLP”。

### 10.3 新增“类型”字段

支持：

- 平扫；
- 增强；
- 4D。

### 10.4 新增“期数”字段

支持增强扫描多期展示。

### 10.5 将“用户确认”改为“状态”

统一展示：

- 正常；
- 待确认；
- 已确认；
- 告警。

### 10.6 支持行展开

展开后展示 Scout、平扫、增强各期和 4D 序列明细。

## 13. 最终建议

本次修改不建议只做视觉层优化，而应优先调整信息架构。

核心改动是：

> 剂量日志主列表从“日志平铺”改为“检查级汇总”，再通过展开明细承载序列、Scout、增强期相和 4D 明细。

这样设计后，后续新增增强扫描、多期剂量统计、DOM 效果分析、剂量告警、患者累计剂量和报告导出时，都可以在现有结构上扩展，不需要重新推翻页面。
