# 验收标准

这里放每个屏幕的"验收标准文档" —— QA 拿着它能逐条勾对/勾错的那种。

## 这是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 描述产品**当前应该**的行为 | 描述产品**为什么**这么做 |
| 每条规则 = 一个测试用例 | 用户研究 / 痛点分析 |
| 列出"待对齐"项（未定义行为） | 设计取舍 / 历史脉络 |
| PM、QA、临床顾问都能读 | 实现细节、代码注释 |

## 怎么用

### 给 QA

1. 拿到屏幕的 .md 文档
2. 按 §3-§7 每一条规则跑一遍，对得上打勾、对不上是 bug
3. 跳过 §9（待对齐项）—— 那些是还没拍板的，不算 bug

### 给 PM

1. 看 §9 待对齐项，找对应的人（开发/临床/自己）拍板
2. 拍板后：把决定写回 §3-§7，从 §9 删除
3. 文档闭环 = 验收基线锁定

### 给开发

1. 改某屏代码前，先看对应 .md 是否描述了这块行为
2. 如果你的改动跟文档不一致：要么改代码、要么改文档（更新需要 PM 同意）

## 文档约定

- 文件名：用中文，跟屏幕名一致（e.g. `患者列表页.md`、`Scout扫描页.md`）
- 章节顺序：固定 §1-§9（用途/布局/Tab/列/显示/操作/分页/边界/待对齐）
- 标"？待对齐 §X.Y" 的地方就是 §9 那一项的引用
- §9 里的"状态"列：待 PM 拍板 / 待开发确认 / 待临床确认 / **BUG** / 已闭环
