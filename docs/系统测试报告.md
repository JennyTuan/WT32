## 测试项 1：服务模式 — 球管预热

**测试路径：** 服务模式 → 球管预热
**测试日期：** 2026-05-12
**测试人员：** JennyTuan

### 缺陷 1：目标热容量输入无上限校验，过高数值触发后端熔断

| 项目 | 内容 |
|---|---|
| **严重等级** | 中 |
| **复现步骤** | 1. 进入服务模式 → 球管预热；2. 在目标热容量输入框输入超过允许范围的数值（例如 >100 或超过当前安全阈值）；3. 点击「开始预热」 |
| **预期结果** | 输入时或点击「开始预热」前，前端即给出明确提示（如"目标热容量需在 20–100% 范围内"），并禁用开始按钮，阻止请求下发 |
| **实际结果** | 前端允许提交 → 后端因数值越限触发熔断 → 前端仅弹出"球管预热中止"，用户无法判断中止原因 |
| **修改建议** | 1. 输入框增加范围校验（MIN=20，MAX=100），越界时在输入框下方红字提示具体允许区间；2. 越界时禁用「开始预热」按钮；3. 后端熔断/中止应返回错误码与原因，前端弹窗显示"因目标值超过安全阈值，预热已中止"而非笼统的"球管预热中止" |

### 缺陷 2：自动曝光未按物理按键即触发，且前端进度条无加载反馈

| 项目 | 内容 |
|---|---|
| **严重等级** | 高（涉及辐射安全规范） |
| **复现步骤** | 1. 进入球管预热；2. 输入合法目标值并点击「开始预热」；3. 观察曝光过程及前端 UI |
| **预期结果** | 1. 自动曝光须等待操作员按下物理曝光手闸（双手按键）后才出射 X 射线，符合 IEC 60601 安全规范；2. 曝光期间前端进度条实时显示当前进度、所处相位（自检/起转/升温/保持）、剩余时间 |
| **实际结果** | 1. 未按物理曝光按键即执行曝光（待确认是真实出射还是仅状态切换）；2. 前端进度条无任何加载/进度变化，用户无法判断预热是否在进行 |
| **影响位置** | 后端曝光触发逻辑 + [WarmupContent.tsx](../ui-review/src/features/service/tubeWarmup/components/WarmupContent.tsx) 进度展示绑定 |
| **修改建议** | 1. **安全侧（必须）**：球管预热曝光必须串联硬件手闸信号，未按下时禁止高压输出；UI 增加"请按住曝光手闸"提示与等待态；2. **UI 侧**：进度条绑定后端实时进度推送（WebSocket/SSE 或轮询），显示百分比、当前相位标题、预计剩余时间；曝光每个 pulse 之间应显示"曝光中 / 间歇冷却"状态 |

## 测试项 2：服务模式 — 空气校正

**测试路径：** 服务模式 → 空气校正
**测试日期：** 2026-05-12
**测试人员：** JennyTuan

### 缺陷 1：协议列表未默认全选

| 项目 | 内容 |
|---|---|
| **严重等级** | 低 |
| **复现步骤** | 进入服务模式 → 空气校正，观察协议/扫描参数列表的默认勾选状态 |
| **预期结果** | 列表所有可校正项默认全部勾选，方便用户一次性执行完整空气校正 |
| **实际结果** | 默认未全选，用户需手动逐项勾选 |
| **修改建议** | 将列表初始状态调整为默认全选；保留用户手动取消的能力 |

### 缺陷 2：点击「空气校正」后蒙层/进度条无任何状态变化，无提示

| 项目 | 内容 |
|---|---|
| **严重等级** | 高 |
| **复现步骤** | 1. 进入空气校正；2. 勾选待校正项；3. 点击「空气校正」按钮；4. 观察蒙层、进度条及提示信息 |
| **预期结果** | 1. 立即弹出执行中蒙层，显示"空气校正进行中"等提示；2. 进度条随后端校正进度实时更新（百分比、当前项、剩余时间） |
| **实际结果** | 蒙层进度条无任何变化，界面无任何文字/弹窗提示，用户无法判断校正是否启动 |
| **修改建议** | 1. 点击后立即切换为"执行中"状态并显示蒙层与说明文案；2. 接入后端进度推送，进度条实时刷新；3. 若后端调用失败，应弹出错误提示并恢复可点击状态 |

### 缺陷 3：点击「中止」无效且无任何反馈

| 项目 | 内容 |
|---|---|
| **严重等级** | 高 |
| **复现步骤** | 1. 启动空气校正后；2. 点击「中止」按钮；3. 观察界面响应 |
| **预期结果** | 1. 弹出二次确认弹窗"确认中止本次空气校正？"；2. 确认后向后端发送中止指令，UI 显示"正在中止…"直至完成；3. 中止成功后回到初始可操作状态，并在日志/提示区记录中止时间与已完成项 |
| **实际结果** | 点击「中止」无任何响应，无弹窗、无状态变化、无日志记录，用户无法停止校正流程 |
| **修改建议** | 1. 补全中止按钮的事件绑定与后端接口调用；2. 增加二次确认弹窗与中止过程提示；3. 中止结果（成功/失败）需有显式反馈 |

| 项目 | 内容 |
|---|---|
| **严重等级** | 高 |
| **复现步骤** | 1. 进入服务模式 → 日常 QA；2. 点击「一键分析」按钮；3. 观察蒙层与界面响应 |
| **预期结果** | 1. 蒙层显示分析进度（当前项/总项数、百分比、预计耗时）；2. 分析完成后自动关闭蒙层并展示结果；3. 蒙层期间应允许中止或在异常时自动退出 |

## 测试项 4：服务模式 — 硬件测试

**测试路径：** 服务模式 → 硬件测试
**测试日期：** 2026-05-12
**测试人员：** JennyTuan

### 缺陷 1：机架模组多个动作返回 SCU 超时错误

| 项目 | 内容 |
|---|---|
| **严重等级** | 高 |
| **复现步骤** | 1. 进入服务模式 → 硬件测试 → 机架模组；2. 分别执行「倾斜控制」「机架定位」「旋转找零」 |
| **预期结果** | 各动作正常下发并执行，返回成功状态及实际位置/角度反馈 |
| **实际结果** | 三项动作均返回报错：`{ code: -1001, message: "SCU cmd: 0x32, timeout" }` |
| **修改建议** | 1. 排查 SCU 0x32 指令链路（前端 → 后端 → SCU 控制器）是否畅通；2. 确认 SCU 固件是否实现对应指令处理；3. 增加超时重试与降级策略；4. 前端错误提示应翻译为用户可读文案（如"机架控制器无响应，请检查通信连接"），而非直接显示原始错误码 |

### 缺陷 2：轨道模组「移动开始（位置目标）」返回 SCU 超时错误

| 项目 | 内容 |
|---|---|
| **严重等级** | 高 |
| **复现步骤** | 1. 进入服务模式 → 硬件测试 → 轨道模组；2. 设置目标位置后执行「移动开始（位置目标）」 |
| **预期结果** | 轨道按设定位置移动并返回成功 |
| **实际结果** | 返回报错：`{ code: -1001, message: "SCU cmd: 0x32, timeout" }` |
| **修改建议** | 同上：定位 SCU 0x32 指令通信链路问题；前端补充友好错误提示与重试入口 |

> **备注：** 上述四项错误均为同一 SCU 指令（0x32）超时，疑似 SCU 通信链路或固件指令未实现的共性问题，建议优先排查 SCU 侧。

## 测试项 8：服务模式 — 手动扫描

**测试路径：** 服务模式 → 手动扫描
**测试日期：** 2026-05-12
**测试人员：** JennyTuan

### 缺陷 1：重建失败导致图像未出，但前端界面无任何提示

| 项目 | 内容 |
|---|---|
| **严重等级** | 高 |
| **复现步骤** | 1. 进入服务模式 → 手动扫描；2. 设置扫描参数并执行扫描；3. 观察机架旋转、图像输出及界面提示 |
