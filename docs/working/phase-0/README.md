# WT32 阶段 0 工作基线

> 本目录记录阶段 0“建立基线与止损”的当前工作材料。内容来自 2026-07-16 的代码与文档观察，不是产品需求批准记录，也不代表真实设备控制、诊断结论、最终剂量计算或安全批准。涉及扫描、剂量、呼吸和影像的未确认事实必须继续使用“模拟、预计、参考、需确认”等限定语。

> **决策状态：已批准。** 2026-07-16，业务负责人明确批准 D0-001 至 D0-009 的建议方案。正式结论见 [WT32 阶段 0 产品基线](../../baseline/2026-07-16-WT32-阶段0产品基线.md)；本目录继续保存批准前的观察证据和实施进度。

## 1. 本批交付

- [五条黄金流程当前基线](WT32_PHASE0_GOLDEN_WORKFLOWS.md)：常规螺旋、常规轴扫、门控、4D、已完成检查图像查看的当前代码路径，以及正常、取消、失败、刷新恢复检查框架。
- [状态与数据来源矩阵](WT32_PHASE0_STATE_SOURCE_MATRIX.md)：业务对象、当前权威来源、缓存、失效、恢复和已知竞争关系。
- [非本机与真机环境问题反馈模板](WT32_NON_LOCAL_TEST_FEEDBACK_TEMPLATE.md)：用于目标机、真机外壳、远程部署或其他非开发机环境的问题复现；不因此扩大 WT32 的真实设备控制边界。

## 2. 证据标记

本目录统一使用以下标记，避免把代码现状、推论和产品结论混在一起：

| 标记 | 含义 | 可否直接作为产品结论 |
| --- | --- | --- |
| **已观察事实** | 能在当前仓库代码、接口或现有权威项目说明中定位到的行为 | 只能说明“当前是什么”，不能自动说明“应该如此” |
| **待运行验证** | 已从代码推导，但尚未在目标环境完整操作验证 | 否 |
| **待验证结论** | 问题或风险有证据，但目标行为仍需更多业务、用户或接口信息 | 否 |
| **需用户决策** | 会改变产品语义、范围、安全边界或验收标准的选择 | 只有明确批准后才可进入基线 |

## 3. 阶段 0 当前边界

本批建议继续做：

- 以现有行为为基准补自动化测试和固定手工检查。
- 修复不会改变产品语义的确定性缺陷，例如状态缓存过期、错误态缺少可恢复入口、刷新后无法回到同一会话。
- 保持协议模板与扫描会话副本隔离。
- 明确标识 mock、静态演示、估算值和后端持久化数据。

本批不直接做：

- 不批准 DOM、剂量阈值、对比剂、门控或 4D 算法事实。
- 不把 4D 与门控合并为同一采集语义。
- 不把静态 DICOM、工程师数据或生成的 mock 结果描述为当前患者的真实检查结果。
- 不在取消、部分结果保留和检查完成口径未决定前，静默改变业务状态。

### 3.1 2026-07-16 首轮执行结果

- 已建立前端 Vitest/jsdom 测试入口，现有 3 个测试文件、17 项测试通过；覆盖工作流计划、选中会话缓存隔离，以及正式序列的最近前置定位像、目标序列、患者/会话/目标/定位像执行绑定、缺失上下文失败关闭和终态判定。
- 后端 37 项测试通过；新增门控轴扫与螺旋一致的 `image_ready + range_confirmed` 前置条件回归，并证明运行中序列必须先收敛、`completed/cancelled` 会话不能重新启动序列或再次确认范围、通用更新接口不能绕过生命周期入口。
- 前端 ESLint 为 0 错误、0 告警；生产构建成功。当前仍有 Cornerstone 编解码依赖的浏览器 externalize 提示，以及主包超过 500 kB 的体积告警，留到性能阶段处理。
- 已修复门控螺旋和门控轴扫确认页遗漏 `range_confirmed=true` 的确定性契约缺口；确认页现在会强制读取最新会话、等待定位像与显示资源就绪、写入范围确认后才进入执行页，失败时停留并提示。门控执行 URL 同时绑定已确认会话、目标序列和前置定位像 ID，并在页面存活期间锁定初始参数；加载、启动、完成、取消均按该绑定复核，缺失/非法模式或中途改写地址参数会失败关闭。当前“终止”会先把仍在运行的模拟序列记为未完成并写明中断原因，再等待会话取消落库后导航；后端禁止直接把含 `running` 序列的会话写成终态。
- 患者确认弹窗现在按正式目标序列显示参考 CTDIvol/DLP，不再固定显示定位像数值；缺少患者或剂量数据时使用 `--`，不再注入虚构默认值。D0-009 已实施：门控范围确认页只保存范围并进入执行准备，患者、目标序列和参考剂量仅在执行页强制确认一次。
- 本地 UI 已实际完成登录、测试患者创建、协议选择、会话创建并进入 `/scout-scan`；当前开发环境的 RespiraScope 健康检查返回 404，因此定位像之后的完整浏览器黄金流程尚未运行通过。该项按环境依赖记录，不据此扩大或推断真实设备能力。
- 可在仓库根目录运行 `./scripts/verify.ps1` 复现后端测试、前端测试、规范检查与生产构建；使用 `-SkipBuild` 可跳过耗时构建。

## 5. 不需要用户逐项决策的工程默认

以下事项可按可逆、最小风险方式继续推进：

- 后端数据库记录作为患者、协议模板、扫描会话和序列执行状态的当前权威来源。
- `localStorage`、`sessionStorage` 和 Dexie 只承担选择上下文、恢复标识或明确版本的快照职责，不作为第二套无约束业务数据库。
- 页面刷新优先用持久化 ID 重新读取权威数据；缓存解析失败或版本不匹配时必须失效，而不是猜测。
- 页面级动画、进度、弹窗和工具选择属于瞬时 UI 状态；若业务要求刷新恢复，就必须先提升为显式、可持久化的工作流状态。
- 静态和生成数据只有在明确的演示模式中才可使用，且不得与当前患者/检查形成未经证实的关联。
