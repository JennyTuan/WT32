## 2. D0-002：独立恢复动作

**状态：已实现，待浏览器验证。**

已落地证据：

- `POST /api/scan-sessions/{scan_session_id}/actions` 提供统一动作入口；动作可通过列表接口回读，序列尝试可通过 attempts 接口追溯。
- `return_to_edit` 将运行中的目标序列安全返回编辑入口，清理不再成立的结果来源，并使关联的旧范围确认失效。
- `retry_series` 只接受失败或中断的目标序列，创建新的可追溯尝试后返回待执行状态，不覆盖旧尝试记录。
- `terminate_exam` 原子收敛运行序列并终止会话，不留下 `running` 序列。
- `action_id` 提供幂等语义；同一动作重放返回原结果，冲突重用被拒绝。
- 动作在取得会话锁后会再次检查 `action_id`，因此两个重叠请求不会因首个请求已经改变状态而把后到请求误判为非法新动作。
- 4D 的 `return_to_edit` / `retry_series` 会在同一事务中失效绑定旧 attempt 的结果，并把结果 ID、版本、阶段和来源 attempt 写入动作审计；新 attempt 可以重新建立结果绑定。
- 页面已改为调用统一动作，不再把“写 `failed` 后再取消”作为正式终止流程。
- 动作台账记录结果会话状态、结果序列状态、下一入口和剂量日志处置。当前不会伪造真实设备剂量；相关字段只描述原型中的模拟或未生成状态。

`finish_with_partial` 的当前约束：

- 正式部分结果模型、完成条件和展示规则尚未批准并落地。
- 请求会明确返回 `409 Conflict`，不会把普通 `completed` 冒充“保留部分结果后结束”，也不会产生状态副作用。
- 因此它是已定义但有意不可用的动作，不应在 UI 或测试中伪装为成功。

仍需验证：常规螺旋、常规轴扫、门控和 4D 在浏览器中的返回修改、失败重试、终止、刷新与重复点击行为。

## 3. D0-003 与 D0-004：执行状态和完成权威

**状态：已实现，待浏览器验证。**

常规轴扫和通用执行约束已经统一：

- 常规轴扫执行绑定患者、会话、唯一目标序列和前置定位像；执行参数来自持久化会话，不从 URL 临时拼接。
- 序列状态采用受控单向迁移：`pending → running → image_ready`，或从 `running` 进入 `failed` / `interrupted`；恢复到待执行状态必须走 D0-002 动作。
- 会话必须处于 `in_progress`，前置定位像必须已经出图且范围已经确认，目标序列才可开始。
- 终态会话和已完成序列不可被后续写请求篡改；并发状态更新通过后端事务和锁保护。
- 会话级元数据、序列结构、参数、重建和 4D 配置写入统一采用“先会话、后序列”锁顺序；执行中的序列不能绕过正式恢复动作修改参数或删除结果绑定。
- 普通检查只在所有计划序列均为 `image_ready` 后由后端完成；查看器只退出查看，不再补写完成状态。
- 4D 不使用普通完成接口，必须走原子 4D finalize 路径。

参数与范围一致性也已收口：

- 常规轴扫和常规螺旋确认页使用参数写入协调器，在确认范围和进入执行前 `flush` 最新防抖写入，并等待在途请求完成。
- 后端检测参数快照变化后会清除关联定位像的 `range_confirmed`；旧范围不能继续解锁新的模拟扫描参数。
- 目标执行再次检查 `image_ready` 定位像、v1 影像来源和最新范围确认，不满足时失败关闭。

仍需验证：1024 × 768 浏览器中的刷新、快速连续修改后立即继续、重复点击、网络响应丢失、终态恢复和跨分支隔离。

- 失败、中断、返回编辑或重试会清理已经失效的来源绑定。

前端查看器依据当前患者、会话、所选序列和 v1 来源选择对应模拟影像。来源缺失、版本不支持、类型不兼容、会话未完成、目标不唯一或历史 4D 结果未就绪时，均显示“本次检查影像不可用”并保留安全退出路径，不静默加载其他患者或固定肺部兜底。

## 6. RespiraScope 兼容模拟服务

**状态：已实现，待浏览器与局域网验证。**

“可访问的 RespiraScope 服务地址”是指运行 WT32 前端的浏览器能够访问模拟器基础地址，而不是只在开发机上存在一个不可达进程。同机开发默认地址为 `http://127.0.0.1:8000`。

当前模拟契约：

| 方法 | 路径 | 原型用途 |
| --- | --- | --- |
| `GET` | `/health` | 返回兼容健康状态，包含 `simulated: true` |
| `POST` | `/startReceive` | 启动模拟接收契约 |
| `WebSocket` | `/socket.io/?EIO=4&transport=websocket` | Engine.IO 4 兼容连接，通过 `/breath` 命名空间发送模拟波形、指标和信号质量 |

Engine.IO 4 心跳由服务端周期发送 ping，客户端 pong 超时会关闭连接；自动化测试覆盖持续心跳与缺失 pong 的超时行为。

接口和 WebSocket 行为已有后端测试并包含在本次 `88/88` 中；Engine.IO 服务端心跳和 pong 超时也有回归覆盖。使用迁移到 head 的隔离临时数据库实际启动 Uvicorn 后，`127.0.0.1:8000` 的健康检查、启动接收、WebSocket 命名空间握手和 `simulated: true` 呼吸事件均通过同机网络冒烟。尚未验证：同机浏览器完整波形流程、可信局域网平板、防火墙、断连、重连和超时。

该服务只用于 WT32 产品和 UI 原型验证。波形、呼吸频率、质量和触发值均为模拟数据，不来自患者或真实设备；它不表示 RespiraScope 真机已集成，也不证明采样率、时钟同步、信号质量或断线语义满足任何设备或临床要求。
