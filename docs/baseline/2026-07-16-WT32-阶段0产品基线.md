# WT32 阶段 0 产品基线

## 1. 批准记录

2026-07-16，业务负责人在本项目任务中明确回复“全部按建议批准”，因此阶段 0 的 D0-001 至 D0-009 自该日期起全部转为已批准产品目标。

本基线适用于 WT32 产品与 UI 验证原型。它不批准真实设备控制、临床诊断、治疗建议、最终剂量计算或剂量批准；相关页面和证据仍须使用“模拟、预计、参考、需确认”等限定语。

## 2. 已批准结论

| ID | 已批准产品基线 | 主要实施含义 |
| --- | --- | --- |
| D0-001 | WT32 保持产品与 UI 验证原型边界；目标机只用于运行、交互和接口验证 | 不因部署到设备外壳或目标机而宣称真实控制、曝光、剂量或安全能力 |
| D0-002 | “返回修改、重试当前序列、终止检查、保留部分结果后结束”是四个独立动作 | 每个动作分别定义会话状态、序列状态、模拟剂量日志、审计记录和下一步入口；未实现正式部分结果模型前不得承诺保留 |
| D0-003 | 常规轴扫需要可观察的模拟执行和合法结束状态 | 不再以 `running` 直接进入查看器作为正式完成路径；若只做参数验证，必须显式标明跳过执行演示且不得伪装成已出图 |
| D0-004 | 检查完成由扫描/后处理编排在满足完成条件后写入后端；查看器只负责退出查看 | 查看器不得补写采集完成；`running` 序列不得直接把会话写为 `completed` |
| D0-005 | 4D 结果、重扫选择和相位选择必须按检查会话持久化并可恢复 | 刷新后恢复同一检查及同一版本结果，不重新生成另一套 mock 结果 |
| D0-006 | 已完成检查只能展示与该会话明确关联的影像 | 缺少关联影像时显示缺失或不可用；不得静默展示其他患者、固定 mock 或静态兜底数据 |
| D0-007 | 阶段 0 查看器只承担扫描质量快速确认和结果关联 | 诊断阅片能力另立需求，不从已有 2D/3D/MPR/测量控件反推已批准范围 |
| D0-008 | 非本机问题证据默认只使用测试或已批准的去标识化数据 | 原始患者标识、原始 DICOM、访问令牌和设备密钥不得进入普通反馈附件；批准渠道和保留期未指定前不传输敏感证据 |
| D0-009 | 门控流程只在执行页进行一次强制患者、目标序列和参考剂量确认 | 范围确认页只保存范围并进入执行准备；两处不得重复确认或使用虚构默认值 |

## 3. 实施顺序

1. 先实现 D0-002、D0-003、D0-004、D0-009，统一工作流动作、序列终态、检查完成和患者确认入口。
2. 再实现 D0-005、D0-006，建立检查级结果与影像关联，移除未经证实的静态兜底。
3. 按 D0-007 收敛查看器验收范围，并在 D0-008 约束下开展目标环境验证。
4. D0-001 是所有阶段持续有效的安全与表述边界。

## 4. 验收约束

- 自动化和人工验收必须区分当前实现、模拟结果和已批准目标。
- 任何会话不得同时处于 `completed/cancelled` 且仍有 `running` 序列。
- 任何已完成检查不得在缺少明确关联时展示为“本次检查影像”。
- 任何模拟剂量和扫描状态都不得表述为最终剂量批准或真实设备执行事实。
- 对本基线的修改需要新的明确批准记录，并保留原基线的历史追溯。
