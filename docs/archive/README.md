# 历史归档说明

本目录保存带明确日期的项目分析、阶段计划和已经失效但仍有追溯价值的文档快照。

## 使用边界

- 归档文档用于还原某一时间点的判断，不自动代表当前产品需求、架构基线或实施承诺。
- 正在收集和验证的需求放在 `docs/working/`。
- 经负责人明确批准的产品基线后续放在 `docs/baseline/`；在该目录建立前，不应把归档结论当作已批准需求。
- 新归档文件使用 `YYYY-MM-DD-主题.md` 命名，并在文档中记录依据、假设和适用边界。
- 如果后续结论发生变化，新增一份带日期的文档并互相引用，不静默改写历史判断。
