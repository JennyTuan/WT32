# 模拟物理按键流程与异常处理

> 本文描述当前已确认的扫描交互流程及界面异常处理，用于原型和前端实现对齐。真实设备控制逻辑以设备研发实现为准。

## 1. 正常流程

### 第一次按键：移动至扫描起始位置

1. 界面显示第一次按键提示。
2. 操作员持续按住模拟物理按键，机器向扫描起始位置移动。
3. 操作员在到位前松开按键，移动停止；界面回到第一次按键提示，可再次按住。
4. 机器到达扫描起始位置后，结束第一次按键引导，切换为第二次按键提示。

### 第二次按键：触发曝光

1. 仅在机器已到扫描起始位置后，显示第二次按键提示。
2. 操作员按下模拟物理按键，发起扫描/曝光下发。
3. 下发成功后，关闭按键提示层，进入扫描执行中的界面。

## 2. 按键提示层的关闭规则

- 第一次按键提前松开：停止本次移动，关闭“移动中”表现，回到第一次按键提示。
- 第一次按键到位：关闭第一次按键提示，显示第二次按键提示。
- 第二次按键下发成功：关闭按键提示层，进入扫描执行中。
- 扫描下发失败、等待超时或发生阻断性硬件异常：立即关闭按键提示层，不让用户停留在无反馈的按键界面。

## 3. 异常处理

### 扫描下发失败

若第二次按键后扫描请求未成功下发：

- 关闭按键提示层。
- 明确提示“扫描下发失败”。
- 提供“重新尝试”和“返回确认”两个操作。
- 重新尝试后，回到本次扫描的按键引导；返回确认则回到扫描确认界面。

### 等待超时

若等待定位结果或扫描下发结果超过设定时间仍未收到结果：

- 关闭当前按键提示层。
- 提示“操作超时，当前扫描状态无法确认”。
- 不应自动进入下一步，也不应继续显示“请按键”。
- 提供重新尝试或返回确认入口；再次操作前应由系统重新确认当前扫描状态。

### 硬件异常

若当前扫描过程中收到硬件异常：

- 立即关闭当前按键提示层，避免用户继续停留在“请按键”的界面。
- 使用全局设备异常提示展示异常信息；不额外叠加流程错误弹窗。
- 一般硬件异常只提示异常信息，不默认增加全局蒙层。
- 仅当设备明确上报为“必须阻断操作”的异常时，才显示全局蒙层并禁止继续操作。
- 异常处理完成后，用户从确认界面重新进入流程，不直接恢复到原按键步骤。

## 4. 错误层级与 UI 一致性

为避免同类异常在不同页面出现不同效果，错误展示必须遵守以下规则：

- 扫描下发失败和等待超时属于当前扫描流程异常：关闭按键提示层，显示流程内错误提示，**不使用全局蒙层**。
- 硬件异常使用现有全局设备异常提示：关闭按键提示层，但不再同时显示流程错误弹窗，避免提示叠加。
- 只有设备明确标识为阻断操作的硬件异常，才使用全局蒙层；不能由前端根据“硬件异常”自行推断。
- 各扫描页面必须复用同一套错误卡片/全局提示组件、标题层级、图标、按钮样式、间距和文案结构；不得为单独页面新增另一种弹窗风格。
- 错误提示只保留必要信息：错误标题、简短原因及明确操作入口。不要在同一张卡片内继续叠加多个提示框、说明框或蒙层。

## 5. 核心原则

- 第一次按键是“按住移动、松开停止”，不是按住一段时间后自动继续移动。
- 第二次按键只在到达扫描起始位置后可用，用于触发扫描/曝光下发。
- 任何失败、超时或硬件异常都必须关闭按键提示层，并给用户明确的下一步操作提示。
- 错误提示的层级和视觉样式必须在全部扫描页面保持一致。
